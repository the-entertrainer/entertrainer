# Compact Screen Map — Introduction to Instructional Design

## Problem being corrected

The current module gates blocks, but it still mounts every unlocked block on one page. A learner who completes a block is therefore asked to keep scrolling through earlier and later material. The redesign converts the same learning sequence into **short, self-contained screens**. A screen has one main teaching purpose, one visual or interaction, and one clear next action.

## Navigation contract

Every screen is rendered alone inside a stable course frame. The top frame shows the current lesson, screen count, and overall progress. The learner can use **Back** to revisit a completed screen, while **Next** remains unavailable until the required read action, selection, game turn, or knowledge check is complete. The current screen is saved locally, so a returning learner resumes at that screen without reopening the full course at the top.

## Screen-length rule

Each screen is limited to one central heading, up to two short instructional paragraphs, one principal visual or interaction, and one action. Dense interactions may occupy their own screen; they are not placed beneath unrelated explanation. Screens use page-level scroll only if a small mobile viewport needs it, but the normal desktop reading target is one to one-and-a-half viewport heights.
