# No-Miss Redesign: Text-First Page Outlines

## Purpose

These outlines define the final reading order and content budget for each public page before any layout is rebuilt. They deliberately avoid visual-component language. A component may be added only after the page content proves that it is needed.

## Home

### Job

Help a first-time visitor understand Naveen’s work and choose a useful path without encountering an archive, filter, professional term, or repeated metadata.

### Reading order

| Order | Content | Constraint |
|---|---|---|
| 1 | **Hello, I’m Naveen. I make complicated things easier to learn.** A two-sentence personal opening that connects hotel-floor experience to current work. | One primary action: **Try a short lesson**. |
| 2 | **Start here.** Four direct routes: Lessons, Projects, Free tools, About. | Each route has a title, one sentence, and one action. No numbering. |
| 3 | **Projects.** Three selected examples: a comic, an interactive explainer, and the AI course. | Image, title, one sentence; duration only on the AI course. |
| 4 | **Free tools.** Three useful browser tools. | One task-led sentence and one action per tool. No card counters. |
| 5 | **A personal close.** One reason Naveen cares about clear explanations and one invitation to get in touch. | One contact action. |

### Content that does not belong

Current edition, archive controls, author lines, project types repeated as badges, arbitrary counts, competing CTAs, and a second About promotion.

## Lessons

### Job

Let visitors try the work without knowing what instructional design means.

### Reading order

1. **Short lessons that make difficult work easier to understand.**
2. One featured four-minute lesson: **How to make instructions easier to follow.**
3. One supporting course entry: **From No AI to Know AI.**
4. A plain note that the lessons are made to be read, tried, and used.

### Content that does not belong

Specialist methodology labels, a course catalogue UI, duplicated progress information outside the course player, or long explanations of learning theory before the visitor can begin.

## Projects

### Job

Show the outcomes Naveen has made and explain why each one mattered.

### Reading order

1. **Projects.** “Courses, stories, and interactive explainers I made for real people with real work to do.”
2. Curated project list, ordered by the clearest examples rather than arbitrary publication date or visual balance.
3. Each project has a direct detail page with five short parts: what it was, what was difficult, what Naveen made, what changed, and what he would do differently now.

### Content that does not belong

Filters unless visitor testing shows a real need, author bylines on Naveen’s own work, auto-generated badges, multiple content-type labels, or an evidence-free “impact” claim.

## Free tools

### Job

Help visitors save time on a concrete task without requiring an account, a sales pitch, or knowledge of learning-design terminology.

### Reading order

1. **Free tools that save time.** “Small browser tools I made after doing the same slow jobs too many times.”
2. StoryGen — plan a story.
3. Cadence — make a calendar.
4. EasyMCQ — make a quiz.
5. Draftly — improve an email.
6. One short privacy note: what visitors type remains in the browser where applicable.

### Content that does not belong

Tool numbers, decorative product categories, generic “web app” badges, large editorial card shells, or explanatory copy that repeats the tool’s button label.

## About

### Job

Make the work feel connected to a real person with a clear path into it.

### Reading order

1. **From hotel floors to learning design.** One plain personal introduction.
2. Five chapters: hospitality, Club Mahindra comic, hotel learning work, building tools, present day.
3. One image, one memory, and one factual location/context label per chapter.
4. One closing reflection and one path to Projects or contact.

### Content that does not belong

Certification-led opening language, repeated role stamps, résumé blocks, or a second CTA that competes with the personal close.

## Experiments and site notes

### Job

Serve curious visitors without diverting first-time visitors from the main site paths.

| Page | Title | Minimum content |
|---|---|---|
| Experiments | **Homepage design experiments** | One plain explanation, a compact list of experiments, and a return path. |
| How this site works | **How this site works** | Technology, original artwork, privacy, and design decisions in plain language. |

Both pages are footer-level destinations. They are not required for a visitor to understand the primary site.

## Shared copy rules

| Situation | Required form |
|---|---|
| Page title | Direct topic first: “Projects,” “Free tools,” “About Naveen,” or “How to…” |
| Supporting sentence | One ordinary-language explanation of the visitor benefit or personal reason. |
| Project/tool presentation | Title, one sentence, optional single decision-relevant detail. |
| Personal note | Specific memory, reason, constraint, or observation; never generic professional positioning. |
| CTA | Verb + outcome: “Try the lesson,” “See the projects,” “Use StoryGen,” “Start a conversation.” |
| Metadata | Include only if a visitor would make a different choice with it; otherwise remove. |

## Phase 2 sign-off condition

Phase 2 is complete when each page can be read as a short text-only outline, every section has a distinct job, and no page depends on layered labels or decorative metadata to make sense. The next phase turns these outlines into the final brand, navigation, and component rules.
