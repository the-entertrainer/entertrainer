# Visual Evidence Standard

## Rule

Every public article must use a relevant **external image, original illustration, or explanatory diagram** when it refers to a real object, place, mechanism, scientific idea, historical event, person, process, or comparison that a reader would understand better by seeing.

> A visual must answer a reader question created by the adjacent text. It must not be used merely to fill space, create mood, or make a page look finished.

## Required editorial decision

Before publishing, list each claim or example that could benefit from visual evidence. For each one, choose the clearest appropriate form:

| Article content | Preferred visual evidence |
|---|---|
| Real object, place, event, person, archive item, or scientific observation | A relevant external image with a visible source credit and a working source link. Use material with a suitable licence or public-domain status. |
| Process, mechanism, sequence, comparison, scale, or cause-and-effect relationship | An original explanatory diagram or illustration with a precise caption. |
| Abstract idea made understandable through a familiar example | An original illustration placed beside that example, with alt text that describes the teaching point. |
| Claim that needs both reality and explanation | Pair an attributed external image with a simple original diagram or annotated explanatory visual. |

## Non-negotiable checks

Each visual must be directly connected to the nearby copy, have specific alt text, include a useful caption, and be readable on a phone. External material must credit the original source in the article. Original visuals must be controlled components rather than uncontrolled image markup.

Do not use generic stock-style imagery, repeated art, image-only metaphors, uncredited material, decorative scene-setting, or an illustration that restates the headline without clarifying the content.

## Publishing gate

An article is not ready to publish until its visual-evidence map has been checked alongside factual sources, sharing metadata, mobile layout, and the project image-policy guard.
